# 設計記録の整理

対象の設計記録と既存の保存方針を確認します。記録の新設・整理が必要な作業で使い、機械的変更や小さなUI調整へ毎回Agent Noteを要求しません。

## 判断に役立つかを読む

制約、採用理由、退けた案、保存・権限・互換性・所有の条件が、今後の判断に必要かを評価します。長さや古さだけで削除・archiveしません。

新しい記録が古い決定を置き換える場合は、完全な置換か一部だけかを確認します。固有の事実を取り込んで統合し、独立した理由は残して相互の関係を記録します。

## 保持・移動・削除

現在の判断に必要なものはactiveへ、歴史に意味があるものは既存のarchiveへ置きます。単なる作業報告や重複は、その情報が他へ残ることとinbound linkを確認して整理します。

archiveが凍結された記録なら、現在の仕様へ書き直しません。後続の記録から置換関係を示します。存在しない本体用manifestや日英中のtripletを、このリポジトリへ要求しません。

変更後はinbound link、現在の参照、必要な設計理由の所在を確認します。秘密情報や非公開の会話を、公開する設計資料へ転記しません。
