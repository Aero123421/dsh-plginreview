# UI・日本語化・フォント

DSHの既存設定画面に追加するUIは、組み込みの部品、余白、色、文字サイズ、選択表現を先に確認します。機能を追加するたびに独自のtoggle・dialog・toastを作ると、見た目と操作が分かれます。

## プロバイダー管理の構成

Piログインと検索プロバイダーで使ってきた構成を、次の設計の出発点にできます。

- 接続・資格情報は設定画面で管理する。
- provider単位のON/OFFを持つ。
- provider内で、使用するモデルや追加ツールを選ぶ。
- チャット側には、設定で有効にした候補だけを出す。
- OFFにしても、接続情報と選択を保存する。

「接続済み」「有効」「選択可能」「現在選択中」は別の状態です。接続済みのproviderをOFFにする操作と、ログアウト・資格情報削除は分けます。

設定に表示するだけでなく、利用時の検査もHostに置きます。古いチャット画面や直接RPCから、OFFのモデル・ツールを使えないようにします。

## 非同期状態を画面に出す

初回取得が終わるまで編集を止めるか、先行編集を保持して取得結果と統合するかを決めます。読み込み前の編集を黙って捨てません。

自動保存は、現在の編集とどの保存要求が対応するかを保持します。古い失敗で新しい入力を戻さず、失敗がまだ現在の編集に関係する場合だけ、項目の近くに理由を出します。

読み取り専用から編集可能になったときも再評価します。保存できない理由を、接続切断、権限、サービス未準備、保存失敗に分けます。

成功表示は、Hostが保存・適用した状態を基準にします。「押せた」「HTTP 200だった」「ローカルstateが変わった」だけで保存完了にしません。

## タブ・カード・長い文言

Remoraでは、日本語の長いタブ名と幅計算が合わず、選択背景が別の項目の下へ移動しました。選択中の実ボタンを基準に描画し、キーボードで選んだ値と同じ状態を使います。

等幅のタブならtrackも等幅にし、内容に応じた幅ならindicatorを実際の位置から求めます。配列indexだけで横位置を算出する方法は、幅が変わるUIには使いません。

設定モーダル内では、window幅より実際の本文領域が狭くなります。カードの列数はコンテナ幅で変えます。長い日本語、URL、package名、版、エラー詳細が幅を押し広げないか確認します。

タブが収まらない場合は、適切な折り返し、短い項目名、横スクロールなどを選びます。文字サイズを際限なく小さくして収めません。

根拠: [Remora UI修正](https://github.com/Aero123421/dsh-remora/pull/3)、[Glass UI設定画面修正](https://github.com/Aero123421/dsh-glassui/pull/2)。

## キーボードとアクセシビリティ

既存部品のkeyboard behaviorを維持します。独自部品が必要なら、少なくとも次を確認します。

| 部品 | 確認する操作・状態 |
| --- | --- |
| tab | 選択状態、tabとtabpanelの関連、矢印キー、focus |
| radio group | 選択値とfocus、矢印キー、Home/End |
| switch | ラベル、現在値、Space、disabledの理由 |
| dialog | focus移動、閉じる操作、元の要素への復帰 |
| エラー表示 | 該当入力との関連、色以外でも分かる状態 |

forced colorsやreduced motionへの対応は、初回読み込みだけで終えません。画面を開いている間の変更にも追従します。一時停止と永久解除を別にし、再開に必要な監視まで消さないようにします。

装飾によってfocus ring、文字コントラスト、クリック対象、スクロールが変わらないかを確認します。Glass UIのようなfilter処理では、ブラウザーの描画差も実物で確認します。

## 日本語化の範囲

製品文字列は型のあるlocale dictionaryに置きます。既存キー、変数placeholder、複数形、エラー条件、動作主体を保って翻訳します。

翻訳しないものには、ユーザー入力、モデル出力、model ID、API token、wire値、元の診断ログがあります。見た目の文字列を変えるために、プロトコル値やモデルへの指示を変更しません。

日本語UIを追加することと、システムプロンプトに「日本語で答える」を追加することは別です。今回の日本語化はUIの表示・言語設定を対象にし、DSHのシステムプロンプトとエージェントの挙動を維持します。

Electronのネイティブダイアログ、terminal、文書previewなど、plugin APIで翻訳・font変更できない面は、その範囲をREADMEに書きます。「画面全体」とだけ案内して境界を隠しません。

## 日本語フォント

日本語化プラグインでは、Noto Sans JPを同梱し、外部font配信に依存せず利用できる構成にしています。fontファイルとOFLのライセンスファイルをpackに含めます。

ユーザーの明示的なfont設定を優先し、言語切り替え・plugin無効化時にはpluginが加えた変更を解除します。UI文字と会話本文の適用範囲を確認し、code・terminalの等幅fontを無条件に置き換えません。

CSSの`font-family`に日本語font名があるだけでは、実際の日本語glyphに使われた証明にはなりません。ブラウザーの描画font情報、例えばCDPの`CSS.getPlatformFontsForNode`で確認します。日本語、英数字、記号の混在とweightも確認します。

特定アプリの非公開font設定を推測して、確定情報としてREADMEに書きません。採用したfontと検証結果を記録します。

## 表示文言を見直す

「このプラグインで提供しない機能は、別のプラグインで追加できます」のように、現在の操作に関係しない案内は設定画面に置きません。利用者が次に行う操作や、現在の失敗を解決するための条件を残します。

| 避ける文言 | 書く内容 |
| --- | --- |
| 「柔軟でシームレスな接続体験を提供します」 | 接続先と、接続するとできること |
| 「詳しくは各種ドキュメントをご確認ください」 | 必要な手順のリンクと、読む条件 |
| 「互換性に問題がある可能性があります」 | 非対応のDSH版・APIと、試した組合せ |
| 「更新完了」だけ | 新しい実行版、または再起動が必要という状態 |
| 「エラーが発生しました」だけ | 失敗した操作、設定を保存できたか、再試行の方法 |

削る際は、権限・期限・保存先・破壊的変更など必要な事実まで消しません。

## 実画面の確認を記録する

DSH版、plugin版、ブラウザー版、locale、theme、viewport幅、実際の本文幅を記録します。RemoraとGlass UIでは、1280・960・600pxなどの実DSH画面で確認しています。ただし、親DSHの固定ナビで非常に狭い本文になる幅まで、モバイル対応済みとは扱っていません。

単独fixtureで再現できる問題はそこで素早く調べ、最後に実DSHへ戻して確認します。スクリーンショットだけで完了にせず、選択、保存、reload、解除まで操作します。
