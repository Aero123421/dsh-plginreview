# よくあった問題と修正例

ここでは、実際の修正PRで扱った問題をまとめます。テスト件数は固定の品質基準にしません。何を再現し、何を確認したかを使います。

## 複数のプラグインに共通する問題

| 問題 | 起きる条件 | 修正・確認 |
| --- | --- | --- |
| 古い取得結果が設定を戻す | 初回取得中に設定保存やログインを行う | 再取得の無効化と通常取得の重複排除を分け、旧世代の成功・失敗を捨てる |
| 解除後に処理が復活する | 通信中・保存中・監視中に無効化する | disposeを境界にし、完了callbackからの再登録も防ぐ |
| 自動保存が新しい編集を巻き戻す | 保存が競合し、古い操作だけ失敗する | 保存を直列化し、操作の識別で現在の編集か判断する |
| GitHubから入れると起動しない | 作業環境の`dist/`だけを使って確認する | GitHub取得物にも生成物を同梱し、CIで再ビルドとの一致を確認する |
| 選択表示と実際の選択が違う | タブ幅が文言の長さで変わる | 実ボタンの選択状態を描画に使い、座標とキーボードを確認する |
| 画面幅では正常、設定欄では崩れる | 左ナビ付きモーダル内で表示する | 利用可能なコンテナ幅で配置を変える |
| 配布物に余計なファイルが入る | 生成物とrelease artifactの出力先を共用する | `dist/`と`release/`を分け、公開ファイルを名前で指定する |

## Remoraで修正した14件

[PR #1](https://github.com/Aero123421/dsh-remora/pull/1)で扱った問題です。遠隔操作は、画面の状態に加え、別プロセス、保存済み状態、Hub、実行中のDSHを確認する必要がありました。

| 番号 | 問題 | 修正の要点 |
| --- | --- | --- |
| R01 | 別DSHプロセスからの緊急停止で、所有プロセスの接続が残る | 保存設定を同期し、所有側の停止とロック解放を待つ |
| R02 | 古い設定snapshotが、新しい設定を上書きする | ロック内で保存済み設定を読み直して判断・更新する |
| R03 | 権限縮小後も`task.get`・`task.wait`が以前の範囲で結果を返す | 現在の権限範囲を再検査し、変更時に待機処理を起こす |
| R04 | キュー取得とキャンセルが競合し、後続の人間のターンまで止める | 実行中になった対象を照合してキャンセルする |
| R05 | 解除・失効後もスケジュールが残る | 所有スケジュールを削除し、失敗分の追跡を残して再処理する |
| R06 | 切断中の完了通知が失われ、Hubでは実行中のままになる | 再接続時にHostから状態を照合し、Hubの記録を更新する |
| R07 | 所有者がクライアントのタスクを確認・取消できない | 所有者操作を通しつつ、権限・対象範囲は同じ境界で検査する |
| R08 | 再送・再起動で同じスケジュールを重複作成する | 冪等キーと要求本文のhashを永続化する |
| R09 | clone中に配置先が変わり、作成・復旧削除が誤った場所に触る | 作成直前に再検査し、削除は所有記録で確認した対象に限定する |
| R10 | LANから`Host: localhost`を送るとローカル扱いになる | HTTPヘッダーに加え、socketの実接続元を検査する |
| R11 | 複数CLIがrefresh tokenを同時更新して壊す | Hubごとのプロセス間ロックと、異常終了したロックの回復を設ける |
| R12 | 新しい保存先より古いkeychain資格情報を使い、ログアウト後も復活する | 保存先の優先順位・移行・削除を整合させる |
| R13 | MCP要求途中の切断で、未回答要求が残る | 要求ごとにプロトコルエラーを返し、次の要求を処理できるようにする |
| R14 | 即座に「対応が必要」を返す監視がbusy loopになる | 待機時間とbackoffを設け、同じ状態で回り続けないようにする |

R08の対策は、すべての処理を一度だけ実行する保証にはなりません。DSHのスケジュール作成とRemoraの記録保存は別の処理です。その間で停止した場合の回復・重複確認も必要です。

その後の[PR #2](https://github.com/Aero123421/dsh-remora/pull/2)では、監査ログの非同期保存前に読み取りが終わる問題を修正しました。読み取りRPCは保存の完了を待ちます。テストではファイルロックを実際に止め、保存待ちの間に読み取りが完了しないことを確認しました。

[PR #3](https://github.com/Aero123421/dsh-remora/pull/3)では、日本語の長いタブ名で選択背景がずれました。等幅を前提にしたindicator計算と実際のタブ幅が合わないため、選択ボタン自身の背景に変更しています。カードの列数も設定パネルの幅で切り替えています。

## Piログイン

[PR #3](https://github.com/Aero123421/dsh-pi-login/pull/3)では、取得中のPromiseを使い回し、設定保存・ログイン・再接続後にも古いsnapshotを採用する問題を修正しました。通常の重複取得はまとめ、強制再取得では古い要求を無効化します。

同じPRで、プラグイン側の10分制限がSDKのDevice Code有効期限15分より短い問題を修正しています。この認証経路では交換処理の猶予を含めて待機期限を調整しました。すべてのOAuthフローを16分待つというルールにはしていません。

[PR #5](https://github.com/Aero123421/dsh-pi-login/pull/5)では、Fastを独立したモデル項目にしました。UIの選択IDとAPIに送るモデルIDを分け、設定画面とHost adapterが同じ候補生成処理を使います。SDKの簡略stream経路が必要なオプションを落とす点も確認しています。

[PR #8](https://github.com/Aero123421/dsh-pi-login/pull/8)では、GitHub導入に必要なビルド済みファイルを同梱し、CIで生成物の一致を確認するようにしました。

## 日本語化とPWA

日本語化の[PR #1](https://github.com/Aero123421/dsh-japanese/pull/1)でも、GitHub導入用のビルド済みファイルとフォントを同梱しました。翻訳辞書だけでなく、実際の描画フォント、ユーザーが指定したフォントの優先、解除時の復元を確認する必要があります。

PWAの[PR #2](https://github.com/Aero123421/dsh-pwa/pull/2)では、pnpm workspace rootへの追加で失敗する手順に`-w`を追加しました。ローカルのDSH profileで追加・削除を確認し、元のロゴのライセンスも配布物に含めています。

ホーム画面用のアイコンとmanifestが入ったことだけで、オフライン対応やスマートフォン向け画面まで完成したとは扱いません。

## 検索プロバイダー

[FxTwitter対応PR #1](https://github.com/Aero123421/dsh-search-providers/pull/1)では、404を検索結果0件に変換しないようにしています。取得できない状態と「投稿が存在しない」を区別できないためです。取得できなかった反応数も0で埋めません。

外部の本文取得APIが対象ページのHTTPステータスを返さない場合、DSHの`web_fetch`と同じ意味にはできません。現在は別ツール`extract_web_page`として提供しています。

## Glass UI

[PR #2](https://github.com/Aero123421/dsh-glassui/pull/2)では、次を修正しました。

- 設定読み込み前の編集が失われる、読み取り専用から編集可能になっても保存が再開しない。
- 古い保存の失敗が、その後の編集を戻す。
- 解除後のcallbackがCSSや監視を再登録する。
- 一時停止中にアクセシビリティ設定の変更を受け取れなくなる。
- DOMのclass・style変更や新しい要素への除外指定が反映されない。
- 大きな設定モーダルを、面積だけで処理対象から除外する。
- Chromiumの版によってfilter描画位置がずれる。
- 設定欄の狭い幅で崩れる、radioのキーボード操作が足りない。
- HTTP環境のclipboard失敗や、診断への背景画像URLの露出。

filterの位置ずれは、ブラウザー版ごとの分岐を増やさず、外側にはみ出す描画を減らす構成で修正しています。対象外のshadowやfocus ringを持つ要素には通常のblurへ戻す経路も残しました。

[PR #3](https://github.com/Aero123421/dsh-glassui/pull/3)では、`dist/`にrelease artifactを重ねてアップロードし、生のJSまでReleaseに載る問題を修正しました。生成物と配布ファイルのディレクトリを分け、tarballと`SHA256SUMS`を明示して公開します。

## 修正済みとして扱わない例

Remoraの確認コミットには、checksumを照合してからDSHのinstallerに渡す更新処理があります。ただし、installerの結果を待って判定せず、ダウンロード先の返却でRPCを終えています。`ChangeResult`の失敗・再起動要求をユーザーに正しく伝える完成例としては扱えません。

この点を含め、更新処理を新しく作る際の設計は[更新ボタン](update-button.md)にまとめています。ここでの文書化は、元のプラグインへの追加修正を意味しません。
