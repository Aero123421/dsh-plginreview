# プロバイダーとツールの拡張

DSHの既存拡張点で追加できる処理は、そこに登録します。認証、候補一覧、生成処理、検索backend、ツール定義、画面は、それぞれの所有者を明確にします。

## 接続・有効化・選択を分ける

設定は、例えば次の状態を別々に持ちます。

```text
provider
  ├─ 認証状態: 接続済み／未接続
  ├─ 有効状態: ON／OFF
  └─ 選択: 使用するmodel・追加toolのID
```

OFFは資格情報削除やログアウトではありません。再びONにしたとき、前の候補選択を復元できるようにします。

チャットのmodel picker、subagent、orchestration、tool実行は、どの候補一覧を使うか調べます。同じ設定で制限したい場合は、共通の候補生成とHost側の検査を使います。

外部のCodex CLIやClaude Codeなどを起動するsubagentは、そのCLI自身の認証・モデル設定を使う場合があります。DSHのpickerと必ず同じになるという前提を置きません。

## モデルのIDと能力

モデル名は表示用です。内部では、provider、選択ID、APIへ送るmodel ID、認証経路、API種別を区別します。

PiログインのFast対応では、同じwire modelに通常版とFast版を作り、Fastの選択IDに`::fast`を付けています。APIには元のmodel IDと対応するservice tierを送ります。これはその実装の規則で、DSH共通のmodel ID形式ではありません。

Fast対応を「名前にGPTが含まれる」だけで決めません。provider、API種別、endpoint、実装が認識している能力を使います。設定画面とadapterが同じ候補生成処理を使い、片方だけにFastが出る状態を防ぎます。

Fast要求が拒否された場合に、黙って通常版へ再送しません。費用・速度・利用条件が変わり、同じ操作を二重に送る原因にもなります。

根拠: [PiのFast対応PR](https://github.com/Aero123421/dsh-pi-login/pull/5)。そのPRの実装確認と、実サービスでの料金・速度・利用可否の確認は別です。

## SDKを更新するときの確認

SDKの便利なwrapperが、必要なオプションをすべて渡すとは限りません。Pi SDKの確認版では、簡略stream経路がFast用のオプションを落とす点を確認しました。

wrapperを避ける場合も、SDKが行っていたreasoning設定、token上限、画像入力、stream event、usage、課金情報、エラー変換を落とさないようにします。

モデル選択IDとwire modelを分けた場合は、保存履歴にも必要な情報を残します。後からSession logを読み直したとき、どの選択を送ったかとAPI側のmodelを再構成できることを確認します。

## OAuthの期限とキャンセル

SDKが通知する認証フローの有効期限を使い、plugin側の固定タイムアウトで先に終了させないようにします。認証コードの入力待ち、ブラウザーでの認証、token交換は別の段階です。

ユーザーのキャンセル、providerによる期限切れ、plugin側のタイムアウト、接続切断を区別します。再試行した旧フローが新しいフローの状態や資格情報を上書きしないことも確認します。

認証はHost側で扱い、snapshotにtokenを入れません。Clientは接続状態や、利用者に提示する認証URL・codeなど、そのフローで必要な情報だけを受け取ります。

## 標準ツールを維持するか、新しいツールにするか

検索プロバイダーでは、DSHの`web_search`をそのまま使い、そのbackendを拡張しています。標準と同名のツールをもう一つ登録する方法ではありません。

| 変更 | 判断 |
| --- | --- |
| 通常検索の提供元だけを変える | 既存backendの拡張点を使う |
| 標準入力と同じ意味で処理できる | multi-query、出典、結果カード、履歴を維持する |
| ニュース・論文・Xなど独立した能力 | 有効にした追加ツールとして登録する |
| 本文は返るが対象HTTP statusは返らない | 標準`web_fetch`と同一視せず、別の本文取得ツールにする |

選択したproviderが失敗した場合、別のproviderへ勝手に切り替えません。問い合わせ先・費用・渡す情報が変わるためです。fallbackを設ける場合は、利用者が分かる設定と結果にします。

## ツール登録と解除

有効な能力だけをmodelに渡します。無効化時は登録を解除し、実行時にも現在の有効状態を検査します。古いSessionが持つツール参照だけで実行できないようにします。

Cordisの登録は`ctx.effect()`や`ctx.on()`など、解除できる仕組みを使います。waterfall listenerで自分の対象でない要求を受けたら`next()`へ委譲します。登録したからといって、他のproviderの要求まで奪いません。

ツールのdescription、schema、出力はモデルが判断に使う契約です。provider固有のraw JSONをそのまま標準出力へ流さず、URL、title、text、時刻、出典、欠損値を検証します。404や欠けた数値を、根拠なく「0件」「0」に変換しません。

## 実APIの確認範囲

adapterのmockテストは、入力変換とエラー処理を確認します。実認証、実APIの権限、返されるmodel、Fast利用、検索品質、費用までは確認できません。

FxTwitterでは投稿URLの取得を実通信で確認しましたが、キーワード検索の404を成功とは扱っていません。有料検索providerのmock成功を、実APIの動作保証としてまとめないでください。
